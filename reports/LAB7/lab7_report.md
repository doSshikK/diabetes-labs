## Реализация

Endpoint `/predict/batch` принимает список объектов и число workers. Пакет
делится на части, которые обрабатываются через `joblib`; число workers ограничено
четырьмя при 10 доступных ядрах. Ошибка части пакета перехватывается, после чего
эта часть повторяется последовательно.

Дрейф контролируется по окнам из 442 строк: PSI и KS по признакам, CSI по
предсказаниям. Проверены чистый поток и сдвиг среднего на два стандартных
отклонения. Дополнительно формируется Evidently-отчёт.

## Производительность

После прогрева выполнено по три повтора на пакете из 4000 строк.

| Workers | Средняя задержка, с | Строк/с | Ускорение |
|---:|---:|---:|---:|
| 1 | 0,00650 | 615119 | 1,000 |
| 4 | 0,01276 | 313370 | 0,509 |

Параллельный режим здесь медленнее: модель и пакет малы, поэтому накладные
расходы joblib выше времени вычисления.

## Дрейф и негативные контроли

- Чистый поток: 0 ложных тревог в трёх окнах.
- Сдвиг среднего: тревога в первом окне после начала дрейфа; задержка 0 окон.
- Сбой одного worker: часть повторена, возвращены 100 из 100 предсказаний.
- Batch endpoint: код 200, число результатов совпадает с числом входов.

## Артефакты

- `parallel_benchmark.csv` — все повторы benchmark.

## Вывод

и обнаружил заданный дрейф без задержки; для малого пакета один worker быстрее.
