## Негативные контроли

- `config_negative_test.log` содержит три успешных отказа: нулевой размер чанка,
  отрицательный alpha и l1_ratio вне диапазона.
- `leakage_test.log` подтверждает обнаружение scaler, обученного на всех данных;
  максимальное расхождение средних равно `0.004523560714`.
- `memory_scaling_check.csv` показывает, что при увеличении логического объёма с
  442 до 44 200 строк максимальный чанк остаётся равным 64 строкам, а измеренный
  пик Python-аллокаций остаётся `0.0170745849609375` МБ.

## Противоречия и невоспроизводимые числа

Противоречий между `lab2_report.md`, `ml_metrics.csv`, `model_manifest.json` и
`run_summary.json` не обнаружено. Числа отчёта сопровождаются ссылкой на таблицу,
журнал, MLflow run ID или `src/lab2/pipeline.py`.

Замечание: абсолютный RSS чанкового прогона 200.984 МБ немного выше RSS полного
прогона 200.688 МБ. Для набора из 442 строк результат определяется общей памятью
Python и MLflow, поэтому преимущество чанков подтверждено отдельной потоковой
проверкой, но не снижением RSS основного прогона.

## Сильные стороны

1. Разбиение train, validation и test не пересекается и проверяется тестом.
2. Один алгоритм `SGDRegressor.partial_fit` используется в обоих режимах.
3. Все итоговые метрики снабжены бутстрэп-интервалами и MLflow run ID.
4. Хеш модели согласован между отчётом и манифестом.
5. Ловушка утечки и три ошибки конфигурации воспроизводимо обнаруживаются.
